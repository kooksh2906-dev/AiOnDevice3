# 블랙박스와 마법의 스케치북 📖

초등학생도 이해할 수 있는 윤형욱 역할 핵심 개념
기준: EdgeScope-Lite Frozen v2.1

이것은 컴퓨터에서 순서대로 실행되는 일반 프로그램이라기보다 FPGA 안에 만든
**아주 빠른 기록 장치**예요. 자동차 블랙박스와 1,024장짜리 마법의 스케치북을
떠올리면 쉽게 이해할 수 있습니다.

---

## 1. 1,024장짜리 마법의 스케치북

이 기록 장치에는 그림을 저장할 수 있는 칸이 정확히 1,024개 있어요.

- 사람이 세면 1번째부터 1,024번째 칸입니다.
- 컴퓨터 주소로는 `0`부터 `1023`까지입니다.
- 마지막 칸 다음은 다시 첫 번째 칸입니다.

```text
0 → 1 → 2 → ... → 1022 → 1023 → 다시 0
```

마지막 칸까지 그림을 그린 뒤에는 새 스케치북을 사지 않고 첫 칸으로 돌아가
가장 오래된 그림 위에 새 그림을 덮어씁니다. 이것을 **원형 버퍼(Circular
Buffer)**라고 해요.

단, 매 clock마다 무조건 한 장씩 그리는 것은 아닙니다. Sampler가
`sample_valid=1`이라는 **“새 그림이 도착했어요!” 표지판**을 보여줄 때만 한 장을
저장하고 다음 칸으로 이동합니다.

처음부터 항상 1,024장이 채워져 있는 것은 아니에요. Buffer가 기록 중이고 유효한
그림이 1,024개 이상 저장된 뒤에는 계속 최신 1,024장을 유지합니다. `DONE`이 되면
더 이상 덮어쓰지 않고 사건 기록이 끝난 순간의 1,024장을 그대로 고정합니다.

---

## 2. 사건 전후를 정확히 512:512로 남기기

기록 장치는 먼저 사건 이전 그림을 충분히 모아야 합니다.

1. 유효한 그림 512장을 먼저 저장합니다.
2. 그러면 `PRE_READY=1`, 즉 **“과거 그림 준비 완료!”**가 됩니다.
3. 그 뒤부터 중요한 사건을 기다립니다.
4. 사건이 발생한 현재 그림도 스케치북에 저장합니다.
5. 사건 그림 뒤로 유효한 그림 511장을 더 저장한 후 멈춥니다.

최종 결과는 정확히 다음과 같습니다.

```text
사건 직전 그림 512장
+ 사건이 발생한 현재 그림 1장
+ 사건 이후 그림 511장
= 총 1,024장
```

“사건 이후 구간 512장”에는 **사건 그림 자체가 포함**됩니다. 그래서 사건이
발생한 뒤 새로 더 저장하는 그림은 512장이 아니라 511장입니다.

컴퓨터가 시간순으로 번호를 붙이면 다음과 같아요.

```text
논리 번호 0~511    : 사건 직전 512장
논리 번호 512      : 사건 그림
논리 번호 513~1023 : 사건 이후 511장
```

사건 그림의 **논리 번호는 항상 512**지만, 스케치북 안의 실제 물리 주소는
0~1023 중 어디든 될 수 있습니다.

또한 사건 알림(`trigger_pulse`)은 반드시 `sample_valid=1`인 현재 그림과 같은
순간에 와야 합니다. 그림이 도착하지 않은 순간의 사건 알림은 저장할 그림이 없기
때문에 Buffer가 받아들이지 않습니다.

## 3. 시간순으로 읽게 해 주는 START_ADDR

스케치북을 빙글빙글 돌며 덮어썼기 때문에 주소 0에 있는 그림이 가장 오래된
그림이라는 보장은 없습니다.

모든 기록이 끝나 `DONE=1`이 됐을 때:

```text
START_ADDR = 마지막으로 그림을 쓴 주소의 다음 주소
```

그 다음 주소가 현재 남아 있는 그림 중 가장 오래된 그림이에요. CPU는
`START_ADDR`부터 1,024장을 읽습니다. 1023에 도착하면 멈추는 것이 아니라 다시
0으로 돌아가 남은 그림을 계속 읽습니다.

```text
실제 주소 = (START_ADDR + 시간순 번호) mod 1024
```

예를 들어 마지막 그림이 주소 6에 저장됐다면 START_ADDR는 7입니다.

```text
7, 8, ... 1023, 0, 1, ... 6
```

이 순서로 읽으면 만화책처럼 처음부터 끝까지 시간순으로 볼 수 있어요.

주의할 점은 Buffer가 그림을 화면에 직접 보여주는 것은 아니라는 것입니다.
Buffer는 `START_ADDR`를 알려주고, MicroBlaze CPU가 그 주소를 이용해 그림을
시간순으로 다시 배열해 UART나 화면으로 보여줍니다.

## 4. 반드시 지켜야 하는 명령 순서

여기에는 두 로봇이 있다고 생각해 봅시다.

- **기록 로봇(Buffer)**: 그림을 스케치북에 저장합니다.
- **사건 감시 로봇(Trigger Engine)**: 사건이 생기면 딱 한 번 종을 울립니다.

사건 감시 로봇은 종을 한 번 울리면 `Clear`하기 전에는 다시 울리지 않는
**one-shot** 방식입니다. 과거 그림 512장이 모이기 전에 감시 로봇부터 켜면,
PREFILL 중 종이 울릴 수 있습니다. 기록 로봇은 아직 준비되지 않아 그 종을
무시하지만, 감시 로봇은 이미 종을 썼기 때문에 다시 울리지 않습니다. 장치가
망가지는 것은 아니지만 Buffer가 계속 사건을 기다려 `DONE`에 도달하지 못할 수
있습니다.

따라서 다음 순서를 반드시 지켜야 합니다.

```text
1. Sampler를 잠시 끄고 원하는 설정을 합니다.
2. Trigger Engine을 Clear합니다. 아직 ARM하지 않습니다.
3. 이전 기록 상태를 Buffer Abort/Clear로 정리합니다.
4. Buffer를 ARM해서 기록을 시작합니다.
5. Sampler를 Enable해서 새 그림을 공급합니다.
6. 유효한 그림 512장이 모여 PRE_READY=1이 될 때까지 기다립니다.
7. Trigger Engine을 다시 Clear한 뒤 ARM합니다.
8. 사건이 발생하고 후속 그림이 저장되어 DONE=1이 될 때까지 기다립니다.
9. DONE 이후 CPU가 BRAM을 읽습니다.
```

가장 짧게 외우면 다음과 같습니다.

```text
Buffer ARM → Sampler Enable → PRE_READY 확인 → Trigger Clear/ARM
```

참고로 512번째 과거 그림과 정확히 같은 순간에 사건 종이 울려도, 그 순간의
상태는 아직 `PREFILL`이므로 종은 무시되고 그림만 저장됩니다. 그 다음부터
`ARMED` 상태가 되어 사건 종을 받을 수 있어요.

사건이 오랫동안 발생하지 않을 수도 있으므로 실제 프로그램에서는 기다리는
시간에 제한(timeout)을 두고, 시간이 지나면 `ABORT`로 기록을 취소하는 것이
안전합니다.

## 5. 문이 두 개 달린 한 권의 스케치북

Capture BRAM은 스케치북 두 권이 아니라 **문이 두 개 달린 한 권의
스케치북(True Dual Port BRAM)**입니다.

| 문 | 사용하는 주체 | 하는 일 |
|---|---|---|
| Port A | Circular Trace Buffer | 새 그림을 빠르게 씀 |
| Port B | MicroBlaze + AXI BRAM Controller | 완료된 그림을 읽음 |

프로젝트 규칙상 CPU는 기록 중인 그림을 함부로 읽지 않고 `DONE=1` 이후 Port B로
읽습니다. 이렇게 하면 같은 칸을 동시에 읽고 쓰면서 생기는 혼란을 피할 수 있어요.

한 sample은 8-bit이지만 스케치북 한 칸은 32-bit입니다.

```text
32-bit 한 칸 = [위쪽 24-bit는 0] + [아래쪽 8-bit가 sample]
```

CPU와 AXI가 32-bit 단위로 읽기 편하게 만들기 위한 약속입니다.

## 6. 페이지 번호와 로봇 주소는 단위가 다르다

Buffer Core는 스케치북의 **몇 번째 칸인지**를 나타내는 word 주소를 사용합니다.

```text
Core word 주소 = 0~1023
```

하지만 Vivado BRAM interface와 CPU는 **몇 번째 byte인지**를 나타내는 주소를
사용합니다. 한 word가 4 bytes이므로 4를 곱해야 합니다.

```text
CPU/BMG byte 주소 = Core word 주소 × 4
```

예:

```text
word 0    → byte 0x000
word 1    → byte 0x004
word 519  → byte 0x81C
word 1023 → byte 0xFFC
```

그래서 전체 Capture BRAM 크기는 다음과 같습니다.

```text
1,024 words × 4 bytes = 4,096 bytes = 4 KiB
```

C 코드에서 `uint32_t *trace_mem`을 사용하면 `trace_mem[i]`가 자동으로
`i × 4` byte 위치를 읽습니다. 따라서 `trace_mem[4*i]`라고 쓰면 안 됩니다.

## 7. AXI4-Lite는 그림을 나르는 길이 아니라 리모컨

Trace Buffer의 AXI4-Lite register는 실제 그림을 저장하는 곳이 아니라 장치를
조종하고 상태를 확인하는 **리모컨**입니다.

### 명령 버튼

| 버튼 | 뜻 |
|---|---|
| ARM | 새 기록 시작 |
| CLEAR_DONE | 완료 표시와 IRQ 해제 |
| ABORT | 진행 중인 기록 취소 |

이 버튼들은 한 번 누르면 자동으로 원래 자리로 돌아오는 W1P 방식입니다. 그래서
`CONTROL` register를 다시 읽으면 0이 나오는 것이 정상입니다.

### 상태 표시등

| 표시등 | 뜻 |
|---|---|
| BUSY | 지금 기록 중 |
| PRE_READY | 사건 이전 그림 512장 준비 완료 |
| TRIGGERED | 사건 알림을 받음 |
| DONE | 최종 1,024장 저장 완료 |

`IRQ`는 DONE이 됐다고 CPU에 알려 주는 종입니다. 한 clock만 울리는 짧은 pulse가
아니라 CPU가 `CLEAR_DONE`, `ABORT` 또는 새 `ARM`을 할 때까지 켜져 있는
active-high level 신호입니다.

실제 그림은 AXI4-Lite CONTROL/STATUS 영역이 아니라 별도의 Capture BRAM 주소
영역에서 읽습니다.

```text
Trace CSR 주소 영역   : 명령과 상태
Capture BRAM 주소 영역: 실제 1,024개 sample
```

`TRACE_REG_START_ADDR=0x08`에서 `0x08`은 START_ADDR 값을 읽기 위한 register
위치(offset)입니다. 실제 시작 주소 값은 CPU가 그 register를 읽어서 얻어야 합니다.

## 8. Vivado에서 스케치북 크기표 확인하기

Vivado가 스케치북을 잘못 크게 만들지 않도록 다음 값이 정확해야 합니다.

```text
BRAM depth = 1024
BRAM width = 32-bit
MEM_SIZE   = 4096 bytes
Clock      = 100 MHz
```

`MEM_SIZE=8192`로 두면 Vivado가 2,048칸짜리 메모리로 바꿀 수 있고 BRAM block도
두 개를 사용할 수 있습니다. 이 프로젝트의 올바른 결과는 1,024×32-bit 메모리와
`RAMB36E1` 하나입니다.

## 9. 헷갈리기 쉬운 말 바로잡기

| 헷갈리는 표현 | 정확한 표현 |
|---|---|
| “Trigger 이후 512장을 더 저장한다.” | Trigger 그림 포함 총 512장이고 이후에는 511장을 더 저장한다. |
| “Trigger 주소는 512다.” | 논리 번호가 512이고 실제 물리 주소는 0~1023 중 하나다. |
| “PREFILL은 512 clock이다.” | PREFILL은 512개의 유효한 sample이다. |
| “항상 1,024장이 들어 있다.” | 처음 채우는 동안은 더 적고, 모두 채운 뒤 최근 1,024장을 유지한다. |
| “Trace CLEAR_DONE을 하면 그림도 모두 지워진다.” | CLEAR_DONE은 완료 상태를 해제하며 BRAM 그림은 그대로 남는다. |
| “Dual Port니까 기록 중 읽어도 항상 안전하다.” | 이 프로젝트는 DONE 이후 CPU read만 보장한다. |
| “START_ADDR는 0x08이다.” | 0x08은 register offset이고 START_ADDR 값은 CPU가 읽는다. |

## 10. 한 줄 요약

> Buffer를 ARM하고 유효한 그림 512장이 모여 PRE_READY가 된 뒤 Trigger를
> Clear/ARM합니다. 사건 그림을 post 첫 번째로 포함하고 유효한 그림 511장을 더
> 저장해 총 1,024장을 만든 다음, CPU가 START_ADDR부터 원형으로 읽어 시간순으로
> 보여주는 FPGA 블랙박스입니다.

### 팀원에게 30초로 설명한다면

```text
제 역할은 1,024개의 sample을 BRAM에 원형 저장하는 Trace Buffer입니다.
Trigger 전 512개와 Trigger를 포함한 후반 512개를 남기며,
Trigger 뒤에는 511개만 더 저장합니다.
완료 후 START_ADDR부터 modulo 1024로 읽으면 시간순 데이터가 됩니다.
통합할 때는 Buffer ARM → Sampler Enable → PRE_READY → Trigger Clear/ARM 순서를
반드시 지켜야 합니다.
```
