# Learning Analysis

## 학습 흐름에서 드러나는 성장

1. **출력에서 입력으로 확장**
   - 앞선 LED Bar 실습의 `DDRD`/`PORTD` 출력 제어에 `DDRG`/`PING` 입력 판독을 결합했습니다.
2. **비트 마스킹 이해**
   - `& ~(1 << n)`으로 다른 핀 설정을 유지하면서 특정 핀만 입력으로 바꾸는 방식을 학습했습니다.
3. **Active-Low 입력 해석**
   - 외부 Pull-up 회로에서 미입력은 High, 입력은 Low가 된다는 하드웨어-소프트웨어 관계를 코드 조건식으로 연결했습니다.
4. **상태를 이용한 기능 제어**
   - `ledData`를 유지하며 Rotate-Left/Rotate-Right 연산으로 다음 LED 패턴을 계산했습니다.
5. **Level Polling의 한계 인식**
   - 버튼을 누르는 동안 동작이 반복되는 단순 폴링에서, 이전 상태와 현재 상태를 비교하는 엣지 이벤트 방식으로 발전했습니다.
6. **모듈화와 재사용성 향상**
   - 버튼 레지스터 주소와 핀 번호, 이전 상태를 구조체에 묶고 `button.c/.h`로 분리했습니다.
7. **구현 신뢰성 개선**
   - 별도 개선 버전에서 디바운싱 지연 후 입력을 다시 확인하고 초기 출력 상태와 타입을 명시했습니다.

## 이력서/면접에 활용 가능한 근거

- ATmega128A의 GPIO 레지스터를 직접 설정하고 Active-Low 버튼 입력과 LED 출력을 연동한 경험
- 비트 마스크와 8-bit 회전 연산을 이용해 다중 버튼 기반 LED 패턴 제어를 구현한 경험
- 폴링 입력의 반복 동작과 기계식 스위치 바운스를 파악하고 상태 전이 기반 버튼 모듈로 개선한 경험
- 하드웨어 레지스터 주소와 핀 상태를 구조체로 추상화하여 소스/헤더 단위로 모듈화한 경험

## 표현 시 주의점

- 현재 코드는 Polling 방식이며 인터럽트 기반 입력으로 구현했다고 설명하면 안 됩니다.
- VER2의 200 ms 지연과 VER3/VER4의 50 ms 지연은 Blocking Delay입니다.
- 보드 재검증 전에는 "실물 동작 검증 완료" 대신 "교육 실습 코드 정리 및 데이터시트 대조 완료"라고 표현하는 것이 정확합니다.
